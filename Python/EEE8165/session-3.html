31 minReading data from a file

Everything so far has used values typed into the code. Real work does not look like that. Data arrives in a file, and the file is nearly always slightly wrong.

1.1 The file

rivers.csv is in this page. It holds 120 readings from three river gauges in the North East, taken every three days from January to April 2026.

The three rivers are real, and so are the places the readings come from. The Tyne is formed where the North Tyne — fed from Kielder Reservoir, the largest artificial lake in northern Europe — meets the South Tyne near Hexham. It then runs east through Newcastle and Gateshead to the sea at Tynemouth. The Wear reaches the sea at Sunderland, a little to the south, and the Coquet further north near Amble.

A river gauge measures three things you will work with all session: how high the water is (level_m), how much of it is going past (flow_cumecs, cubic metres per second) and how warm it is (temp_c).

CSV means comma-separated values. It is the plainest useful data format there is: one line per row, commas between the fields, and the first line naming the columns.

station,date,level_m,flow_cumecs,temp_c
Tyne,2026-01-01,12.2,192.6,10.1
Wear,2026-01-01,7.28,103.0,9.5

You open a file the same way you would anywhere else. Pyodide gives this page a virtual file system, so the code below is exactly what you would write on your own machine.

with open("rivers.csv") as handle:
    text = handle.read()

with closes the file for you when the block ends, even if something goes wrong inside it. Use it every time you open a file; there is no reason not to.

1.2 Cutting text into pieces

handle.read() gives you the whole file as one long string — every line, every comma, run together. Everything in this lesson starts by cutting that string up, so spend two minutes on the tool that does it.

Definition. text.split(separator) cuts a string wherever the separator appears and returns a list of the pieces. The separator itself is thrown away.

The examples below have nothing to do with rivers, so you can see the mechanism on its own:

What you write Cuts at What you get back
"north sea coast".split() any run of spaces ['north', 'sea', 'coast']
"red,amber,green".split(",") every comma ['red', 'amber', 'green']
"2026-01-01".split("-") every hyphen ['2026', '01', '01']
"name\tvalue".split("\t") every tab ['name', 'value']
"first\nsecond".splitlines() the line endings ['first', 'second']

Four things to take from that table.

You always get a list of strings, never numbers. "2026-01-01".split("-") gives ['2026', '01', '01'], not three integers. Converting is your job, and it is the next exercise.

split() with no separator is a special case: it cuts on whitespace, and treats any run of it as one cut. "one two".split() gives two pieces, not four.

An empty piece is a real piece. "red,,green".split(",") gives ['red', '', 'green'] — three items, the middle one an empty string. That is how a missing value arrives in a CSV, and you will handle exactly this later in the lesson.

Count the pieces with len. You met len on strings in Session 1 and on lists in Session 2; it does both. len("red,amber,green".split(",")) is 3.

Use splitlines(), not split("\n")

They look interchangeable and they are not. Text files almost always end with a line ending, and split dutifully reports the nothing that follows it:

"a\nb\n".split("\n")      ->  ['a', 'b', '']     three items, the last empty
"a\nb\n".splitlines()      ->  ['a', 'b']         two items

rivers.csv ends that way, so split("\n") would tell you the file has 123 lines when it has 122, and every count you derived from it would be one too many. splitlines() is the right tool for lines. Reach for split(",") only once you are working on a single line.

Exercise 3

Skip the gaps

Add up the levels across every row, count how many you added, and skip the rows where the level is missing.

The level arrives as text, so it has to be converted. fields[2] is a string like "12.2", and you cannot add a string to a running total — use float(...) on it first, exactly as in the previous exercise.

That conversion is why the missing rows have to go. A missing value appears in the file as nothing at all between two commas, so the field is the empty string "" — and there is no number for float("") to produce:

float("12.2")   ->  12.2
float("")       ->  ValueError: could not convert string to float: ''

A ValueError stops the program. So test for the empty field first, and skip that row before you reach the conversion. Remember that an empty string is falsy, so if fields[2] == "": and if not fields[2]: both work.

Keep three running values: total of the levels, counted for the rows you used, and skipped for the rows you did not.

Show a worked solution
with open("rivers.csv") as handle:
    lines = handle.read().splitlines()

total = 0.0
counted = 0
skipped = 0

for line in lines[1:]:
    fields = line.split(",")
    if fields[2] == "":
        skipped += 1
        continue
    total += float(fields[2])
    counted += 1

print(f"{counted} readings, {skipped} skipped, mean {total / counted:.2f} m")

25 minWhy NumPy is fast

Everything you have written so far loops in Python. For a hundred readings that is fine. For a million it is not, and the reason is worth understanding before you reach for the library that fixes it.

2.1 What a Python list really holds

A Python list does not hold numbers. It holds addresses — notes saying where each number is kept.

Think of a numbered locker room. The list is a row of slips of paper, each one giving a locker number. The numbers themselves are in the lockers, spread all over the room. To read one, you take the slip, walk to that locker, open it.

Each locker is more than the number, too. Python keeps the type and some bookkeeping alongside it, so one whole number takes about 28 bytes — roughly seven times what the number itself needs.

A NumPy array is the other thing entirely. There are no slips and no lockers. The numbers sit side by side in one block, all the same type, nothing else stored with them.

C is the language NumPy’s inner workings are written in. It is a compiled language — the kind from Session 1 that is translated all at once, ahead of time — and it is very fast at exactly this sort of repetitive arithmetic. You will not write any C in this course. You only need to know that it is there, underneath, already translated and waiting.

Two things follow, and together they are the whole story.

  1. Less memory, and it is all in one place. A computer fetches memory in blocks, not one number at a time. When the next number is right next door, it has already arrived. When it is somewhere else entirely, everything waits for it.
  2. The repeating moves into C. a + b on two arrays does the whole loop in NumPy’s own compiled code. The same thing over a Python list runs Python once for every single item.

2.2 Asking NumPy to do the work

That is the reason. This is the syntax, and it is the only new thing you need for the next exercise.

An array carries its own methods, and each one runs the whole loop inside NumPy rather than in Python:

import numpy as np

readings = np.array([12.2, 7.28, 2.41, 9.05])

print(readings.sum())
print(readings.mean())
print(readings.max())

30.94
7.735
12.2
On an array Gives you
array.sum() the total
array.mean() the average
array.min(), array.max() the smallest and largest
len(array) how many items, as for a list

Note where the method sits. It is readings.sum() — written after the array, with a dot — in the same way .append is written after a list. That is NumPy’s own sum, not Python’s built-in sum(...) function, and the next exercise times the difference between them.

Show a worked solution
import time
import numpy as np

n = 1_000_000

for v in values:
    loop_total += v
loop_seconds = time.perf_counter() - start

builtin_seconds = time.perf_counter() - start

start = time.perf_counter()

numpy_seconds = time.perf_counter() - start

print(f"python loop : {loop_seconds * 1000:8.1f} ms")
print(f"sum()       : {builtin_seconds * 1000:8.1f} ms")
print(f"numpy       : {numpy_seconds * 1000:8.1f} ms")
print(f"numpy is {loop_seconds / numpy_seconds:,.0f} times faster than the loop")

Look at the totals as well as the times. All three agree — but only because the array was created with dtype=np.int64. The next section explains why that matters more than it looks.

The middle row is the interesting one. sum() is compiled code too, but it still has to unwrap each Python integer, so it lands between the two. The gap NumPy opens is not about C alone — it is about the data being raw numbers in the first place.

This is why Session 1 said Python was slow

Lesson 1 of the first session said an interpreted language runs 10 to 100 times slower than a compiled one, and promised the speed would come back later.

This is how. You do not rewrite your program in C. You keep writing Python, and you arrange for the inner loop — the part that runs a million times — to happen inside a library that is already compiled.

Your code stays readable. The work happens somewhere fast. That trade is the entire reason scientific Python exists.

2.4 An array can overflow, quietly

An array has one fixed type, and a fixed type has a largest value it can hold. Go past it and the number wraps around rather than raising an error.

This page runs a 32-bit build of Python, so np.arange(1_000_000) here gives an array of int32, whose largest value is 2,147,483,647. Adding up a million numbers overflows that, and the total comes back as 1783293664 — a plausible looking number that is simply wrong.

That is why the exercise above says dtype=np.int64.

On your own laptop the default is usually int64, so the same code would give the right answer there and the wrong answer here. Silent differences between machines are exactly the sort of thing that wastes a week.

Largest value
int32 2,147,483,647
int64 about 9.2 × 10¹⁸
float64 about 1.8 × 10³⁰⁸, but only ~15 significant digits

Rule. A Python integer grows as large as you need. A NumPy integer does not. When you are summing many values, say which dtype you want.

24 minArrays, masks and broadcasting

An array is not just a faster list. It behaves differently, and the differences are what make it useful.

3.1 Every item has the same type

Definition. An array’s dtype is the single type shared by every element. .shape is a tuple giving its size along each dimension.

np.array([1, 2, 3])          dtype int32 here (int64 on most laptops),   shape (3,)
np.array([1.0, 2.0])         dtype float64, shape (2,)
np.zeros((2, 3))             dtype float64, shape (2, 3)

One shared type is exactly what buys the speed from the last lesson. It also means an array cannot hold mixed data: put a string into an array of numbers and NumPy converts everything to strings rather than keeping a mixture.

3.2 Arithmetic applies to the whole array

This is the habit to build. Where you would have written a loop, write the operation on the array itself.

levels = np.array([12.2, 7.28, 1.92])

levels * 100        every value multiplied
levels - levels.mean()   every value shifted
levels > 5          every value compared

The last one is worth stopping on. Comparing an array with a number gives you an array of True and False, one per element. NumPy calls that a mask.

3.3 Selecting with a mask

Put a mask inside the square brackets and you get back only the elements where it was True.

levels[levels > 5]           just the values above 5

Read it inside out: levels > 5 builds the mask, and levels[...] selects with it. This one line replaces a loop, an if and an append.

Combine conditions with & (and) and | (or). The brackets are required — & binds more tightly than >, so levels > 5 & levels < 12 is a syntax error waiting to confuse you.

levels[(levels > 5) & (levels < 12)]

3.4 Broadcasting

Two arrays of the same shape combine element by element. An array and a single number also combine — the number is applied to every element.

Definition. Broadcasting is NumPy’s rule for combining arrays of different shapes by stretching the smaller one.

levels - levels.mean()       array minus one number
levels / flows               two arrays, element by element

The second only works if the shapes match. Mismatched shapes raise a ValueError that names both, which is one of the more helpful error messages you will meet.

Put values on a common scale

Different measurements have different units and ranges. To compare them, or to cluster them later, you first put them on a common scale.

The usual way is to subtract the mean and divide by the standard deviation, so the result has mean 0 and spread 1. NumPy has .mean() and .std().

27 minpandas: tables with names

NumPy holds numbers. Real data has columns with names, a mixture of types, and gaps. pandas is NumPy with those things added.

4.1 DataFrame and Series

Definition. A DataFrame is a table: named columns, each holding one type. A Series is a single column.

A Series is not a Python list, and printing one shows its index alongside the values. .tolist() converts it to an ordinary list when a plain one is what you want — to print, or to compare against a list you wrote yourself.

Reading the file is one line. Everything you wrote in the first lesson — splitting, converting, skipping blanks — pandas does for you.

import pandas as pd

rivers = pd.read_csv("rivers.csv")

Four methods tell you what you have, and you should use all four before you trust anything:
df.shape rows and columns
df.head() the first five rows
df.info() column names, types, and how many values are missing
df.describe() count, mean, min, max for the numeric columns

4.2 Selecting rows and columns

Two accessors, and the difference matters.

Selects by
df.loc[rows, columns] label — the index value and the column name
df.iloc[rows, columns] position — integers, like a list 
rivers.loc[0, "level_m"]        the level in the first row
rivers.loc[rivers["temp_c"] > 11, :]     every row above 11 degrees
rivers.iloc[0:3, 0:2]           the first three rows, first two columns

Masks work exactly as they did in NumPy, which is not a coincidence — a pandas column is a NumPy array with a label attached.

5.5 The most dangerous mistake in pandas

There are two ways to write “set this column, for these rows”. One of them works.

df.loc[mask, "flow"] = value      correct
df["flow"][mask] = value          does nothing at all

The second is chained indexing: it selects the column, and then assigns into whatever that selection returned. In modern pandas the selection is always a copy, so the assignment lands on a temporary object that is discarded immediately. Your original frame is untouched.

It does not raise. It prints a warning, and warnings are easy to miss.

Why this one is worth remembering

Assistants write this constantly, and for a good reason: it used to work.

For years pandas would sometimes update the original frame and sometimes not, depending on the memory layout, and printed a SettingWithCopyWarning when it could not tell. Millions of lines of tutorial and Stack Overflow code use the chained form, and that is what these models learned from.

pandas 3.0 settled it: every indexing result behaves as a copy, so chained assignment never works. Consistent, predictable — and it breaks a decade of copied examples, with only a warning to tell you.

Rule. One set of brackets to select, then assign. If you see a ][ before an =, it is wrong.

This is the clearest example in the whole course of an assistant confidently producing code that is several years out of date. The code runs. The output looks plausible. Nothing tells you except the warning, and only if you read it.

Almost every question about data is really a question about groups. What is the average per station? Which month was wettest? How many readings per site?

6.1 Split, apply, combine

Definition. groupby splits the rows into groups, applies a calculation to each group, and combines the answers into one result.

A Series prints with its index down the side, which is hard to read in a checked exercise, so these pages call .to_dict() on it — that turns a Series into an ordinary dictionary, keys being the index.

This is the same rule as lessons 2, 3 and 4: keep the work inside the library. Whenever your code hands data back to Python one piece at a time, you have stepped off the fast path.

30 minFinding groups yourself

The scatter plot showed three clouds because you coloured them by station. This lesson finds the same three groups without being told the station names — using only the measurements.

That is clustering, and the standard method is k-means.

8.1 The algorithm

It is four steps, and you already know how to write all of them.

  1. Choose k starting points, called centres.
  2. Assign every reading to its nearest centre.
  3. Update each centre to the mean of the readings assigned to it.
  4. Repeat 2 and 3 until nothing moves.

That is the whole thing. There is no hidden mathematics.

8.2 Standardise first

Level runs from about 2 to 15. Flow runs from 20 to 240. Distance in raw units would be almost entirely flow, and level would be ignored.

So put both on a common scale first — subtract the mean, divide by the standard deviation, exactly as in the arrays lesson.

Rule. Any method that measures distance needs its inputs on comparable scales. Forgetting this is the single most common mistake in clustering.

What k-means cannot do

It cannot tell you what k should be. You told it three. Give it four and it will cheerfully return four clusters, splitting one river down the middle.

It also assumes clusters are round and roughly the same size, because it measures plain distance to a centre. Long thin clusters, or one large and one tiny, and it does badly.

And it depends on where the centres start. Ours began at the first three readings; a different start can converge somewhere worse. Real implementations run it several times from different starts and keep the best.

None of that makes it useless. It makes it a tool with a shape, and knowing the shape is what tells you when to reach for something else.

20 minThe same thing in three lines

You wrote k-means. Here it is from a library.

from sklearn.cluster import KMeans

model = KMeans(n_clusters=3, n_init=10, random_state=0)
labels = model.fit_predict(Xs)

Three lines against your thirty, and it is faster, handles the awkward cases, and runs from several starting points to avoid a bad one.

This is the right way round. Writing it yourself first is what makes those three lines readable. You know what n_clusters does because you chose k. You know why n_init exists because you saw that the starting centres matter.

random_state=0 is worth explaining. k-means starts from random centres, so without it you get slightly different answers every run. Fixing the seed makes your result reproducible — someone else running your code gets your numbers.

That is a research skill, not a Python trick. A result nobody can reproduce is not a result.

Reproducibility, briefly

Three habits, and they cost nothing:

Set the seed. Any function with randomness in it takes a seed. Fix it, and your numbers are the same tomorrow.

Record the versions. pd.__version__ and np.__version__ change behaviour between releases — pandas 3.0’s chained-assignment rule is exactly such a change. Write them down with your results.

Keep the cleaning in the code, not in the spreadsheet. If you fix a value by hand, nobody can repeat it, including you in six months.

10.1 Installing Python

There is more than one Python on most computers, and picking the wrong one is the commonest first problem.

Route Use it when
python.org you want plain Python and nothing else
The Microsoft Store you are on Windows and want the simplest possible install
Anaconda or Miniconda you want the scientific stack and a package manager in one

On Windows, tick “Add Python to PATH” on the first screen of the installer. Almost every “python is not recognised” question comes from this box being unticked.

On macOS, the python3 that is already there belongs to the operating system. Leave it alone and install your own.

Check it worked by opening a terminal and running (on Windows):

python --version
pip --version

On macOS and Linux, type:

python3 --version
pip3 --version

10.2 Environments, and why they exist

Two projects need different versions of pandas. Install them both system-wide and one of them breaks.

Definition. A virtual environment is a private folder of packages belonging to one project.

python -m venv .venv                 create it
source .venv/bin/activate            switch to it, macOS and Linux
.venv\Scripts\activate               switch to it, Windows
pip install pandas matplotlib        install into it
pip freeze > requirements.txt        write down exactly what you installed

That last line matters more than it looks. requirements.txt is how somebody else — or you, on another machine — reproduces what you had.

Rule. One environment per project. Never pip install into the system Python.

10.3 Where to write the code

Three tools, and they are for different things.

Jupyter notebooks

A notebook mixes code, output and prose in one document. You run one cell at a time and the results stay on screen. It is the standard way to do exploratory data analysis, and it is what most published research code looks like.

pip install jupyterlab
jupyter lab

It opens in your browser and looks a little like this worksheet — which is not a coincidence.

The hazard is worth knowing before you meet it. Cells run in whatever order you click them, and a name from a cell you have since deleted stays in memory. A notebook can work perfectly for you and fail for the next person, because you ran things in an order you no longer remember.

Before you share one, use Restart and run all and check it still works from an empty kernel. If it does not, it was never really working.

Google Colab is Jupyter hosted by Google, with the libraries pre-installed and a free GPU. Convenient — but your data and code go to Google’s servers, which is worth a thought before uploading anything you did not generate yourself.

VS Code

A general editor, free, and the most common choice for Python now. Install it, then install the Python extension from Microsoft; the Jupyter extension lets you run notebooks inside it too.

Good at: everything, eventually. Weak at: telling you what to do next.

PyCharm

A dedicated Python IDE from JetBrains. The Community edition is free, and students get Professional free with a university email.

Good at: refactoring, navigating a large codebase, debugging, managing environments for you. Weak at: being small — it is a lot of program if all you are doing is a single script.

Best for
Jupyter exploring data, showing results, teaching
VS Code almost anything; the safe default
PyCharm a large project you will live in for months

A recommendation. Start with VS Code and Jupyter notebooks inside it. Move to PyCharm when a project grows big enough that you are getting lost in it.

10.4 Version control

The one skill this course has no room for and you should learn next.

Git records every version of your work, lets you undo anything, and lets several people work on one project without overwriting each other. GitHub is a website that hosts Git repositories.

Four commands do most of it:

git init                     start tracking this folder
git add .                    stage what has changed
git commit -m "message"      save a version, with a note
git push                     send it to GitHub

This matters more for research than for programming. A results folder called final_v3_ACTUAL_use_this.xlsx is a version control system, just a bad one.

Software Carpentry’s Git lesson is free, short, and written for researchers rather than software engineers.

10.6 Using an assistant well

You have fixed eighteen pieces of machine-written code across three sessions. The mistakes were real: a shared default list, pop(0) in a queue, an off-by-one range, a round that does not round up, chained assignment that silently does nothing, k-means on unscaled data.

Every one of them ran without error.

Four habits are what separates using these tools from being used by them.

  1. Ask for small pieces. One function you can read beats a script you cannot.
  2. Decide the answer first. Have one input whose output you already know, and check it. This found more bugs in this course than reading the code did.
  3. Check the age of the idea. Models learn from years of text. pandas and numpy have changed; the assistant may not have noticed.
  4. Say what you used. Which tool, what you asked, what you changed. It is normal engineering practice to record where something came from, and it is the difference between using a tool and passing off its output.

Record how you used AI in your own work

When you write up a project, keep a short note like this. It takes two minutes and it answers the question before anyone asks it.
Tool and version
What you asked it
What you kept unchanged
What you changed, and why
What it got wrong

Your School will have its own policy on declaring this. Read it. The safe default, everywhere, is to say what you did.

11.1 Summary

Data lives in files, and files are wrong. This one had a duplicate, a sensor fault, two gaps and inconsistent capitalisation. None of them would have raised an error; all of them would have changed your answer.

NumPy is fast because of memory, not magic. One block of numbers, all one type, with the repeating done in compiled code. That is also why an array can overflow and a Python integer cannot.

pandas is NumPy with names. Columns, an index, mixed types, and a real answer for missing data.

One set of brackets to select, then assign. df.loc[mask, "col"] = value. Chained assignment silently does nothing in modern pandas.

groupby splits, applies and combines. Almost every question about data is a question about groups.

Plot before you summarise. The mean level of 7 metres described no river in the file. One histogram showed why.

Standardise before measuring distance. Otherwise the largest column decides the answer on its own.

You wrote k-means before you called it. That is why the three lines from scikit-learn are readable rather than magic.
